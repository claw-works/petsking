# WebM 桌宠素材生产规范

> 目标：用 AI 生成视频 + 绿幕静态收尾帧，产出一套透明 VP9-alpha webm，
> 喂给本项目的动画链前端（`pet.js`）驱动。本文覆盖：需要哪些素材、每个素材的
> 统一规格、姿势/分镜要求、游戏内截静态图的取景要点、AI 提示词模板、
> 绿幕抠像转码脚本、前端接入参数。

---

## 0. 核心设计（先理解，再生产）

三条贯穿全流程的原则：

1. **脚线统一**：所有动画里角色的「脚」都踩在同一条水平线上（脚线）。切换动画时脚不上下跳。
2. **收尾帧统一**：每个动作视频都以**同一张「标准待机站姿」定格**收尾（就是你要在游戏里截的绿幕静态图）。
   这样任何动作播完都能无缝接回待机，动画链才顺滑。
3. **绿幕 → 透明**：所有视频（含收尾定格）用绿幕拍/生成，后期抠像转成透明 webm。

**收尾帧 = 待机起始姿势**。它既是 `idle` 动画的第一帧，也是所有动作的最后一帧。先把它定死，再做别的。

---

## 1. 最小素材集（先做这些，跑通再扩）

驱动前端（`pet.js`）要求每个「动画类别」至少一个。最小可跑集如下：

| # | 素材名 | 类别 | 朝向 | 循环? | 说明 |
|---|--------|------|------|-------|------|
| 1 | `idle` | 待机 | **正面** | 是（首尾一致） | 默认状态，出现最多。轻微呼吸/眨眼即可 |
| 2 | `turn` | 转向 | 正面→侧 | 否 | 播完朝向翻转，用于「回头/转身」过渡 |
| 3 | `walk-right` | 移动 | **侧面朝右** | 否 | 向右走的动作（位移由前端加，见 §6） |
| 4 | `walk-left` | 移动 | **侧面朝左** | 否 | 向左走（可由 right 镜像，见下） |
| 5 | `drag` | 拖拽 | 正面 | 是 | 被拎起悬空的姿势，循环 |
| 6 | `click-happy` | 点击回应 | 正面 | 否 | 点击触发，播完回待机 |

**绝对下限**：`idle` + `drag` + `click-happy` 三个就能让桌宠「站着 + 可点 + 可拖」。
加 `walk-right/left` 就能到处走。`turn` 可最后做。

> **朝向说明**：idle / drag / click / 日常动作都做**正面**（面对用户，符合你的设定）。
> 只有**走路是侧面**（面朝行进方向）。walk-left 可以直接用 walk-right 视频在前端 `scaleX(-1)` 镜像，
> 省一半工作量——但**若角色左右不对称**（如刘海偏分、单侧背包），镜像会穿帮，那就左右各生成一条。

## 2. 统一规格（每条 webm 必须一致）

| 项 | 规格 | 说明 |
|----|------|------|
| **画幅比例** | **16:9** | 全套统一。基准分辨率 **640×360**（可整体放大，如 1280×720，但比例锁死 16:9） |
| **分辨率** | **640×360**，全套完全一致 | 混用会导致脚线/命中框错位。定一个就别改 |
| **帧率** | **24fps**，全套统一 | 与现有 blue-whale 实测一致 |
| **脚线位置** | 画面高度的 **≈91.67%** 处（y≈330/360） | 见 §3。角色脚底落在这条线，全套一致 |
| **水平位置** | 角色主体**水平居中** | 命中框中心在画面正中 |
| **编码** | VP9 + alpha，webm | 透明必须 VP9 或 AV1，不能用 H.264 |
| **背景** | 全透明（抠像后） | 生产时是绿幕，转码后透明 |
| **时长** | idle/drag 循环段 3~6s；动作 2~5s | move 首尾各留静止段，见 §6 |

> 这套规格取自现有 `blue-whale` 素材（`assets/thumb/` 下 91 个 webm），实测全部
> **640×360 / 16:9 / 24fps / VP9**，脚线在 330/360 ≈ 91.67%。新角色沿用同一套规格，
> 前端 `geometry` 参数（`aspect:1.7778, feetRatio:0.9167`）可直接复用，无需改代码。
>
> **关于透明的注意**：转码时输入 `yuva420p`，但成品 VP9 webm 用 `ffprobe` 探测会显示
> `pix_fmt=yuv420p` 且带 `ALPHA_MODE=1` 标记——alpha 通道单独存在隐藏流里，这是
> VP9 存透明的标准形态，**不代表没抠透明**。浏览器 `<video>` 会正确渲染透明背景。

## 3. 脚线怎么定（关键）

「脚线」是角色脚底所在的水平线。约定放在**画面高度的 91.67%** 处（脚下留约 8.3% 空间，给影子/悬空余量），即 640×360 画面里 y≈330px。

- 例：360px 高的画面，脚线在 y≈330px（从顶算）；放大到 720px 高则脚线在 y≈660px（比例不变）。
- **所有动作**——待机、走路、跳跃、被拖拽——角色脚底都对齐这条线（跳跃时起跳点在这条线）。
- 截收尾静态图时，角色站姿的脚底也要在这条线上。

做法：生产时在画布上拉一条参考线（91.67% 高度），角色脚底贴线。转码时不裁剪、不缩放位置，保持一致。

## 4. 收尾静态帧：游戏内怎么截（你问的重点）

这张图是**整套素材的基准**，务必讲究：

**取景要求**
- **姿势**：标准待机站姿——正面朝向镜头/用户，双脚自然站立，双手自然垂放或轻微姿态。**不要**动作幅度大的姿势（那样别的动作接不回来）。这是"原点姿势"。
- **朝向**：正面（面对用户）。角色目视前方。
- **相机**：正对角色，**平视**（相机高度≈角色胸口），不要俯视/仰视/斜角，否则和别的帧透视不一致。
- **构图**：角色**水平居中**，**脚底落在 91.67% 脚线**，头顶留白约 8~10%，全身完整入镜（含脚、含头发/配饰最高点）。
- **背景**：纯绿幕。游戏里若不能开绿幕，选一个**尽量纯色、且和角色颜色反差大**的背景（避免角色身上有和背景同色的部分）。绿色最好，其次品红/蓝。角色身上**不要有和绿幕同色**的元素。
- **光照**：均匀、正面光，避免强阴影和背光（阴影会带进抠像边缘）。
- **无 UI**：截图时关掉血条/准星/字幕/水印等一切 UI 叠加。
- **分辨率**：≥ 目标分辨率，宁大勿小（缩小不糊，放大糊）。

**操作建议**
- 找一个**静止待机动作**的游戏角色，等它站定不动的一帧截图。
- 用游戏自带的拍照模式/自由镜头（若有）摆正相机、隐藏 UI。
- 连截几张挑最正、最居中、无遮挡的一张。

## 5. AI 视频生成提示词（模板）

假设流程：**收尾静态图**（游戏截图）→ 图生视频（如可灵/即梦/Runway/Pika 等）→ 得到动作视频，
且让视频**结尾定格回这张静态图**。核心是每条提示词都要求：**同一角色、正面、绿幕、脚不移动（除走路）、结尾回到站立待机**。

> 通用后缀（每条都加）：
> `纯绿幕背景(#00FF00)，全身入镜，脚底始终在同一水平线，正面平视机位，光照均匀无强阴影，
> 无UI无字幕，角色外观/服装/配色全程一致，动作循环流畅，结尾回到自然站立待机姿势定格。`

**① idle 待机（循环）**
```
角色正面站立，非常轻微的呼吸起伏与偶尔眨眼，重心不移动，双手自然垂放。
细微、缓慢、可无缝循环。[通用后缀]
```

**② walk-right 向右走（侧面）**
```
角色转为侧面朝右，原地做行走动作（迈步、手臂前后摆动），像在走路但身体保持画面居中
（位移后期添加）。开头0.5秒和结尾0.5秒静止站立。[通用后缀]
```
（walk-left：把"朝右"改"朝左"；若打算前端镜像则不必单独生成）

**③ drag 被拖拽（循环）**
```
角色像被无形的手从头顶拎起、双脚离地悬空，四肢自然下垂并轻微摆动晃荡，
表情略惊讶。可无缝循环。[通用后缀]
```

**④ click-happy 点击回应（开心）**
```
角色正面，被戳了一下的开心反应：轻轻跳一下并挥手/比心，然后回到站立。
动作短促(1~2秒)，结尾回到待机站姿。[通用后缀]
```

**⑤ turn 转向**
```
角色从正面缓慢转身到侧面再回，或做一个回头动作，结尾停在自然站立。[通用后缀]
```

**提示词通用要点**
- 反复强调「同一角色/服装/配色一致」——图生视频最容易漂移。
- 强调「脚底在同一水平线」「身体居中不位移」——移动交给前端。
- 强调「结尾回到站立待机」——保证能接回 idle。
- 时长设短（2~5s），越短越稳、越省抠像功夫。
- 若工具支持**首帧/尾帧指定**：把收尾静态图设为**尾帧**，效果最稳。

## 6. 移动动画的首尾静止段（leadSec / tailSec）

走路视频里**角色本身不做水平位移**——位移是前端用 CSS 把整个宠物挪过去，视频只演"迈腿的动作"。
前端约定：动画**前 2 秒、后 2 秒**角色原地不动（`leadSec=2, tailSec=2`），中间才是行进段，
前端在中间段同步平移宠物位置。

所以 walk 视频结构：`[0~2s 站立] → [2s~末-2s 原地走] → [末-2s~末 站立收尾]`。
（数值可调，但要和前端 config 一致。短视频可把 lead/tail 改小，如各 0.5s。）

## 7. 前端接入（16:9，通过 pet.json geometry 配置，无需改代码）

WebM 渲染器（`pet-lib/renderers/webm.js`）**不写死尺寸**，脚线对齐与画幅比例全靠素材包
`pet.json` 里的 `geometry` 字段驱动。新角色沿用 blue-whale 的 16:9 规格，直接复制这两个值：

```jsonc
// pets/<新角色>/pet.json
"geometry": {
  "aspect": 1.7778,      // 16:9 画幅比（640/360）
  "feetRatio": 0.9167    // 脚线 = 91.67% 高（330/360）
}
```

要点：
- `feetRatio` 必须等于你生产时用的脚线比例（91.67%）。全套素材脚线一致，这个值就对。
- `aspect` 锁 16:9。只要全套素材都是 16:9，分辨率放大到 1280×720 也不用改这个值。
- 渲染器用**百分比**定位，因此改分辨率无需改代码；只有换**比例**（如真要走 4:3）才需改 `aspect`/`feetRatio`。
- 命中/拖拽热区当前由场景与 `size` 推导，无需在素材侧配置。

> 现有 `blue-whale` 就是这么接的：`geometry:{ aspect:1.7778, feetRatio:0.9167 }` 对应
> 640×360 素材。新角色只要素材规格一致，把 geometry 原样抄过去即可。

## 8. 绿幕抠像 → 透明 webm（ffmpeg）

前提：本机有 ffmpeg 且编译了 libvpx-vp9。基础命令：

```sh
ffmpeg -i input_greenscreen.mp4 -vf "\
colorkey=0x00FF00:0.30:0.10,\
format=yuva420p,\
scale=640:360:force_original_aspect_ratio=decrease,\
pad=640:360:(ow-iw)/2:(oh-ih)/2:color=0x00000000\
" -c:v libvpx-vp9 -pix_fmt yuva420p -b:v 0 -crf 30 -an output.webm
```

参数说明与调优：
- `colorkey=0x00FF00:0.30:0.10`：抠绿。第一个数=相似度（0.2~0.4，越大扣得越狠但易吃边缘），
  第二个=边缘混合（0.05~0.15）。**按素材实测调**。绿幕不纯时先试 `chromakey`（在 YUV 空间，通常更干净）：
  `chromakey=0x00FF00:0.10:0.08`
- 边缘残留绿边可加去溢色：在滤镜链里加 `despill`（新版 ffmpeg）或手动降绿。
- `scale + pad`：统一到目标分辨率 **640×360** 并居中补透明边。若素材已是 640×360 可省略。
- `-crf 30`：质量/体积平衡，20~35 之间调；`-b:v 0` 走 CRF 模式。
- **透明必须 `-pix_fmt yuva420p` + libvpx-vp9**。

**收尾定格帧**若是单张图，想做成"静止 webm"或直接当最后一帧：
```sh
# 单图 → 2秒静止透明 webm（当独立 idle 兜底）
ffmpeg -loop 1 -i idle_still_green.png -t 2 -vf "colorkey=0x00FF00:0.30:0.10,format=yuva420p" \
  -c:v libvpx-vp9 -pix_fmt yuva420p -crf 30 idle-still.webm
```

**质检**：转码后在浏览器里放（`<video>` 叠在花色背景上）确认：无绿边、无黑底、循环无跳变、脚线不飘。

## 10. 生产顺序（建议）

1. **先定收尾静态图**（游戏截图，§4 要求）——这是基准，先冻结。
2. 用它生成 **idle**，转码，接入前端，确认脚线/居中/循环 OK（这一步验证整条管线）。
3. 再做 **drag + click-happy**（正面动作，好做）。
4. 最后做 **walk-right**（侧面），验证移动位移；需要再做 walk-left 或镜像。
5. `turn` 及更多日常动作按需扩。

跑通 1~2 步后，把第一条 webm 用 `ffprobe` 确认是 **640×360 / 24fps / VP9 且带 ALPHA_MODE=1**，
在浏览器叠花色背景上验证无绿边、循环无跳变、脚线不飘，即可批量生产其余动作。
新角色的 `pet.json` 直接复制 blue-whale 的 `geometry`（`aspect:1.7778, feetRatio:0.9167`）。
