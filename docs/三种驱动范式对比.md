# 三种桌宠驱动范式对比 · pet-study

本项目研究「同一套美术资源（91 个透明 VP9-alpha webm），能用几种完全不同的『驱动逻辑』
表达出桌宠行为」。参考了三个 DeepSeek Harness (DSH) 桌宠插件，把它们各自的**驱动内核**
剥离出来，脱离 DSH 服务器 / Cordis / React / 原生窗口，用纯静态页面 + 同一批 webm 复刻。

三个复刻互相独立，各占一个目录，共享 `assets/thumb/*.webm`：

| 目录 | 复刻对象 | 驱动范式 | 一句话 |
|------|----------|----------|--------|
| `whale/` | [whale-on-desk](https://github.com/cookiesheep/whale-on-desk) | **Agent 事件 → 优先级状态机** | 宠物是 Agent 的「状态指示器」，还会长大 |
| `desktop-pet/` | [dsh-desktop-pet](https://github.com/sereinmono/dsh-desktop-pet) | **确定性语义状态机** | 同为状态指示器，但更精简、纯函数、多任务折叠 |
| `sprite/` | [dsh-pet-sprite](https://github.com/BlackBearCC/dsh-pet-sprite) | **物理平台跳跃游戏** | 宠物是个游戏角色，不看 Agent，只受重力驱动 |

对照组是项目根目录原有的 `pet.js`（**概率动画链**：加权掷骰永不停止地衔接播放）。

---

## 核心差异：下一个动画由谁决定？

四种方案最本质的区别，是「**如何选择下一个要播的动画**」。

```
概率链 (原 pet.js)   随机掷骰 → 加权抽取下一个动画，与外部世界无关
whale-on-desk        Agent 事件流 → 折叠成优先级状态 → 查表得动画（响应式）
dsh-desktop-pet      归一化事件 → 纯函数分类 → 多任务优先级折叠 → 查表得姿势（确定式）
dsh-pet-sprite       物理引擎每帧算位置 → 物理状态(地面/空中/移动) → 得动画（模拟式）
```

| 维度 | 概率链 | whale | desktop-pet | sprite |
|------|--------|-------|-------------|--------|
| 驱动源 | 随机数 | Agent 事件 | 归一化事件 | 重力 + 输入 |
| 是否响应外部 | 否 | 是 | 是 | 交互(键鼠) |
| 随机性 | 高 | 有（transient 抽选/掷骰） | **无（纯函数）** | 有（自主规划） |
| 状态数 | 无状态 | 25 | 10 语义态 | 2 物理态 |
| 动画选择 | 加权池 | 状态→单 webm | 语义→姿势→webm 池 | 物理态→webm |
| 位置 | 屏幕游走 | 固定角+可拖 | 固定角 | 平台跳跃 |
| 额外系统 | — | 成长(XP/称号)+音效 | 多任务折叠 | 物理+养成 |

## 一、whale/ — Agent 事件驱动的优先级状态机

**内核**：`state-machine.js`（移植自 `lib/pet-machine.mjs`）

宠物状态不是随机的，而是**监听 Agent 干什么**：思考 → `think`，调工具 → `tool-run`，
连续读文件 → `review`，请求批准 → `glass-tap`（贴屏敲玻璃），完成 → `celebrate`。

三类状态：
- **durable**（工作态）：`idle / swim-fast / think / tool-run / review / sleep`，持续到下个 durable 转移
- **transient**（反应态）：3 秒短动画，播完回 durable，如 `celebrate / startled / sink`
- **forced**：demo 覆盖

**优先级仲裁**是关键：`glass-tap`(100) > `poked-flail`(90) > … > `idle`(0)。
高优先级 transient 拒绝被低优先级打断；审批期间 `glass-tap` 锁死一切，直到 `approval/decided`。

```js
// 优先级仲裁：新 transient 优先级 < 当前生效 transient 则拒绝
_setTransient(next) {
  const curP = 当前 transient 有效 ? STATE_PRIORITY[当前] : -1;
  if (STATE_PRIORITY[next] < curP) return; // 压不过，忽略
  ...
}
```

**成长系统**（`growth.js`，移植自 `lib/growth.mjs`）：零负反馈。
`xpForLevel(L) = 50·L·(L-1)/2`，称号是纯谓词（满足即解锁）。完成任务 +10 XP，开会话 +5 XP，
工作态每 15s 累积活跃时长。持久化走 `localStorage`。

**渲染**（`client.js`）：双 `<video>` 交叉淡入切换、状态→webm、缺失回退 `idle`、
位置记忆、点击/双击→戳、长按→摸头。状态改变时用 Web Audio **实时合成音效**（零音频文件）。

由于没有真 DSH 服务器，页面提供「模拟 Agent 事件」面板代替真实 `session/event`，
并有「▶ 跑一个完整任务回合」按钮串起整条事件链。

**验证**：优先级仲裁、review 判定、XP/称号数值共 15 项单测通过。

## 二、desktop-pet/ — 确定性语义状态机

**内核**：`core.js`（移植自 `src/core/{types,PetStateResolver,TaskStateRegistry,PetStateMachine}.ts`）

和 whale 同为「状态指示器」，但设计哲学不同——**强调确定性和可测试性**：

1. **事件→状态是纯函数**（`resolveEvent`），无随机、无副作用、无 I/O：
   ```js
   tool.started + 工具名匹配 /edit|write|patch/  → CODING
   tool.started + 工具名匹配 /bash|shell|exec/    → RUNNING_COMMAND
   task.completed                                  → SUCCESS (flash)
   ```
2. **10 个 SemanticState 折叠到 6 个动画姿势**（`SEMANTIC_TO_POSE`）：状态多、姿势少，
   THINKING/WORKING/CODING/RUNNING_COMMAND 全映射到 `running`。
3. **多任务优先级折叠**（最大亮点）：多个 Agent 并发时，每个 taskId 各维护一份状态，
   全局取**最高优先级**：
   ```
   WAITING_FOR_USER(60) > ERROR(50) > WORKING/CODING/CMD(40)
     > THINKING(30) > SUCCESS(20) > STARTING(10) > IDLE(0) > SLEEPING(-10)
   ```
4. **定时回落**：flash 态（SUCCESS/ERROR/STARTING）2s 回 IDLE；长静默自动 SLEEPING。
   `IDLE_PROTECTED` 集合防止 turn 末尾的 idle ping 打断 flash。

原版是**原生透明桌面窗口 + sprite sheet 逐帧**（Win32/X11 via koffi，sharp 解码）。
这里用 webm 表达同一套状态逻辑：每个姿势配一组候选 webm，idle 时每 `IDLE_FREQ_MS`
随机换变体（复刻 `AnimationController` 的 idle 变化机制）。

页面提供单任务事件面板 + 「▶ 多任务并发折叠演示」（同开 3 个 Agent 看优先级压制）+
`/pet` 式命令输入框（复刻原版 `ctx.commands` 注册的 `/pet <state>`）。

**与 whale 的关键区别**：whale 有随机 transient 抽选、有成长/音效、状态语义偏「情绪化」
（excited/proud/shy/chase-fish）；desktop-pet 完全确定、无随机、状态语义偏「工程化」，
且专门处理多 Agent 并发。

**验证**：工具分类、多任务折叠、flash 共 8 项单测通过。

## 三、sprite/ — 物理平台跳跃游戏

**内核**：`physics.js`（移植自 `ChatPet.tsx` 的物理循环）+ `nurture.js`（养成）

彻底不同的范式：宠物**不看 Agent 状态**，它是个受重力驱动的**平台跳跃游戏角色**。

- **平台识别**：把页面上的元素当平台（原版是 `[data-chat-flow-key]` 用户气泡，
  且只有用户气泡可落脚、助手气泡不可——保护文字可读性）。本复刻用 `.plat` div 模拟聊天气泡。
- **物理引擎**（每帧 `update`）：重力 `G=1500`、行走、一段跳 `JUMPV`、空中二段跳 `SKILLV`、
  下降时检测落到平台、支撑消失则下落（气泡滚走宠物会掉下来）。
  ```js
  _jumpTo(p) {                        // 反推所需初速跳向目标平台
    const need = Math.sqrt(2*G*Math.max(20, p.y - this.h + 16));
    if (need > SKILLV) return false;  // 跳不到就放弃这个目标
    this.vy = need; this.state = "air";
  }
  ```
- **自主 vs 玩家控制**：自主模式每 1.2~3s 随机规划（原地走 / 跳到更高平台）；
  点竞技场空白处接管为玩家控制（A/D 移动、空格跳、S 穿透下落），**10 秒无输入自动回自主**。
- **养成系统**（`nurture.js`）：三属性 `mood/power/health` 带衰减与联动
  （power 饿了扣 health，mood 好了回 health）；等级二次曲线 `cumExp(L)=2500·(L-1)²`，
  等级越高衰减越慢；**token 经济**——用户输入按字符估算 token 扣 power，助手输出长度转 XP。
  属性还反过来驱动动画：饿了播 `哈欠连天`，心情好播 `可爱宅舞`。

原版是 **24×28 像素调色板逐帧手绘精灵**；本复刻用 webm 承载，物理作用在 webm 舞台的 (x,h) 上，
物理状态（ground/move/air）+ 属性覆盖 → 切换 webm。

**验证**：等级曲线、token 经济、care 效果、衰减联动共 10 项单测通过。

## 用 webm 复刻像素/GIF 的适配要点

三个原版分别用 **GIF**（whale）、**sprite sheet 逐帧**（desktop-pet）、**像素调色板手绘**（sprite），
本项目统一用 **透明 VP9-alpha webm**。适配时的共性处理：

1. **双 video 交叉淡入**：切动画时用两个 `<video>` 交替，`opacity` 过渡，避免黑屏闪烁。
2. **脚线对齐**：所有 webm 在 640×360 画布上脚踩 `y=330`，渲染时统一下移 `bottomPad`，
   保证不同动画的「脚」在同一水平线（源自根目录 `pet.js` 的 `_applyBottomPad`）。
3. **朝向**：`transform: scaleX(-1)` 水平镜像。
4. **一对多**：GIF/sprite 是「一状态一文件」，webm 池允许「一姿势多候选」，天然支持 idle 变体。

## 如何运行

静态服务器根目录设为本项目目录（webm 需经 HTTP 加载，`file://` 不行）：

```sh
cd pet-study
python3 -m http.server 8799
```

然后分别打开：
- 概率链（对照）：http://localhost:8799/index.html
- whale：http://localhost:8799/whale/index.html
- desktop-pet：http://localhost:8799/desktop-pet/index.html
- sprite：http://localhost:8799/sprite/index.html
